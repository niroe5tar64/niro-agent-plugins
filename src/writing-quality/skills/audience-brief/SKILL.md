# Audience Brief — 執筆前の読者宣言

## 目的

文書の最適な冗長度・結束度は読者の既有知識に依存し、「常に簡潔・高結束が正解」は成り立たない（McNamara & Kintsch 1996 ほか — `docs/research-basis.md` 参照）。書き始める前に読者を確定し、設計パラメータを宣言することで、生成後に削るより安いコストで読みやすさを作り込む。

## このスキルの責務

- 3 質問以内で読者宣言に必要な情報を確定する（会話・既存資料から自明な項目は質問しない）
- 読者宣言を成果物として提示し、ユーザーの合意を得る
- 以後の執筆・修正はこの宣言に照らして判断する

## 必読ドキュメント

実行前にプラグインルート配下の `docs/principles.md`（§1 執筆前に決めること、§5 境界条件）を Read すること。

プラグインルートは Claude Code が提供する base directory で解決する（`<base_dir>/docs/...` の形）。取得できない場合は Glob で `**/writing-quality/docs/principles.md` を探して Read する。

## 読者宣言のフォーマット

```markdown
## 読者宣言
- 読者: <誰が読むか。複数なら主読者を 1 つ決める>
- 既有知識: <読者がすでに知っていること / 知らないこと>
- 読後の行動: <読者に期待する判断・行動。本文の取捨選択基準>
- 分量予算: <目安の長さ。読者の読み方（流し読み / 精読）を反映>
- 冗長度: <低（高知識読者・要点のみ） / 中 / 高（初学者・説明的反復あり）>
- 用語方針: <初出で定義が必要な用語 / 使わない用語>
```

## 手順

### Step 1: 情報収集

会話と既存資料から埋められる項目を先に埋め、不足分だけを 1 質問ずつ確認する（最大 3 問）。

### Step 2: 宣言の提示と合意

読者宣言を提示し、合意を得る。継続利用する場合は保存先（文書冒頭のコメント・別ファイル等）を 1 質問で確認する。

### Step 3: 執筆への適用

宣言に合意が取れたら、以後の執筆で次を守る。

- 結論・判断事項を文書の先頭に置く
- 段落ごとに「この段落は読後の行動に寄与するか」を自問し、寄与しない段落は書かない
- 宣言した冗長度・用語方針から逸脱する場合は理由を明示する

執筆済みの文書に対しては、宣言との差分を指摘したうえで `deslop` スキルでの点検を提案する。
