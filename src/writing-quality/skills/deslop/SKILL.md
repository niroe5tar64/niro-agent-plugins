# Deslop — 認知負荷ベースの文書簡素化レビュー

## 目的

生成 AI が書いた（または AI 臭くなった）文書を、認知科学の知見に基づくチェックリストで点検し、読み手の処理コストを下げる。

「短くすること」自体は目的ではない。読み手が内容の心的表象（状況モデル）を構築するコストを下げることが目的であり、読者によっては説明の追加が正解になる場面もある（`docs/principles.md` の境界条件を参照）。

## このスキルの責務

- 文書を分析し、修正候補を影響の大きい順に 1 件ずつ提示する
- 各候補にユーザーの承認を得てから修正を適用する
- 意味・事実・数値・固有名詞・約束事項を変えない。削除・修正の根拠を必ず示す
- 文体の好みは押し付けない。チェックリスト外の指摘は「参考」と明示する

## 必読ドキュメント

実行前にプラグインルート配下の `docs/principles.md`（チェックリストと境界条件）を Read すること。科学的根拠まで確認する場合は `docs/research-basis.md` を参照する。

プラグインルートは Claude Code が提供する base directory で解決する（`<base_dir>/docs/...` の形）。取得できない場合は Glob で `**/writing-quality/docs/principles.md` を探して Read する。

## 手順

### Step 1: 対象と読者の確認

- 対象ファイル（または文章）を特定する。指定が無ければ 1 質問で確認する。
- 想定読者（誰が読むか・何を知っているか・読後に何をするか）を確認する。文書や会話から自明なら質問せず、推定を宣言して進める。読者宣言（`audience-brief` の成果物）が既にあればそれを使う。

### Step 2: 分析

`docs/principles.md` の §2〜§4 を適用し、以下のカテゴリで候補を洗い出す。

| カテゴリ | 検出対象 |
|---|---|
| 無関連情報 | 目的に貢献しない補足・こぼれ話・「ちなみに」（seductive details） |
| 冗長反復 | 言い換え反復・直前内容の要約・同語反復の結論（redundancy effect） |
| 存在理由不明 | 消しても読者の理解・判断が変わらない段落 |
| 結束性の欠如 | 用語ゆれ・指示語の飛び・前提の後出し・話題の不連続 |
| 高負荷構文 | 過剰な名詞化・一文多義・深い入れ子（element interactivity） |
| AI 定型表現 | 「重要なのは〜という点です」「まさに」等の水増し定型句 |
| 結論の埋没 | 判断・アクションが文書後半に埋まっている |

### Step 3: 候補の提示と承認

- 影響の大きい順に 1 件ずつ提示する。複数候補を一括提示しない。
- 各候補で「該当箇所 / カテゴリ / 修正案 / 根拠」を示し、承認・修正・スキップを確認する。

### Step 4: 適用と報告

- 承認された候補のみ Edit で適用する。
- 全候補の処理後、適用サマリ（件数・削減量・見送った候補とその理由）を報告する。

## してはならないこと

- 承認前の一括修正
- 事実・数値・固有名詞・約束事項の削除や変更
- 初学者向け文書での説明的冗長性の機械的削除（expertise reversal — `docs/principles.md` §5 参照）
- チェックリストに根拠を持たない「好みの書き換え」
